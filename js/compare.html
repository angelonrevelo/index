Same 1,322-professor Ateneo registrar snapshot. Same queries. All three running in this tab.

The two are complementary in a way neither can fix by tuning.

Their matcher does infix; index cannot. gracia has to reach DIVINAGRACIA, GERALD G. A term dictionary stores divinagracia as one token, so gracia is neither a prefix of it nor within edit distance — an FST walk can never arrive there. It offers GARCIA at distance 1 instead: a reasonable guess, and the wrong professor.

index does typos; their matcher cannot. ABACNA and ABAAN require the typed characters not to appear in order, which is exactly what all four of their routes require.

So the third pane runs both and ranks literal matches above fuzzy ones — a character the user typed is evidence, an edit the engine guessed is inference, and inference must not displace evidence. That is index’s own internal rule (typo_bucket outranks BM25) applied one level up.

Badges. literal matched characters the user actually typed — their matcher’s route. bN is index’s typo bucket: b0 exact term, b1 one edit away, b3 matched a different token. Bucket is the primary sort key, so an exact match is never displaced by a fuzzy one.

prefix: true is not optional. Without it index matches the last token as a complete term, so a half-typed query — which is every query until the user stops typing — finds nothing: pen returns 0 instead of 6, gar 0 instead of 10. The first version of this page omitted the flag and badly understated the engine.

Not compared. Their shipped shard also carries 7,911 courses, department sublabels and comment counts, and ranks courses below professors. This corpus is the 1,322-professor snapshot both sides can read, so their sublabel tiers and comment_count tiebreak never fire — with one kind and a constant count they are no-ops, so the order here is exactly theirs.
